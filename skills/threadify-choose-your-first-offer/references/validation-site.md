# Optional ChatGPT Sites validation handoff

Run only after the user opts in. Discover and read the installed ChatGPT Sites building and hosting skills, following their current supported tools. Do not substitute a local HTML file and call it a deployed ChatGPT Site. If Sites is unavailable, explain the missing capability and offer a draft brief; installation or a different host is a separate choice.

## Copy and offer design

Use an original, truthful adaptation of Alex Hormozi's $100M Offers value equation: make the desired outcome concrete, explain why the delivery can work using actual proof, shorten the path to a useful result, and reduce the buyer's work. Primary reference: [Acquisition.com value checklist](https://www.acquisition.com/hubfs/Offer%20Checklists%20-%20PDF%20Downloads/Pricing-Value-Checklist.pdf?hsLang=en). These are design principles, not a claim of endorsement or guaranteed conversion.

- Lead with the specific audience and bounded outcome, then explain the problem in their language.
- Show tangible deliverables, the steps, what the buyer must do, and realistic timing. Translate each feature into a benefit supported by the confirmed offer.
- Address genuine obstacles and objections. Include bonuses, price, capacity limits, deadlines, refund terms or guarantees only when supplied and confirmed, feasible, and real. Never manufacture urgency, testimonials, results, savings or customer counts.
- Use actual evidence where permission permits. If there is no customer proof, show a clearly labeled sample or explain the process; do not disguise the creator's plan as a case study.
- State who it is and is not for, scope limits, and one clear next step. Interest is not a booking or purchase. Keep public claims within the reviewed decision boundary.

## Build, deploy, verify

1. Prepare a redacted brief from the confirmed decision: audience, problem, outcome, delivery model, deliverables, approved proof, limitations and CTA. Ask only for essential missing choices. No raw Threads bodies or confidential source records leave local custody.
2. Build a responsive, accessible page with clear visual hierarchy, benefit-led copy, offer details, objections/FAQ and one primary CTA. Optimize for a measurable validation action; do not claim “high converting” before measurement.
3. For an interest form, establish the real storage destination, minimum fields, explicit follow-up consent and clear privacy wording. Do not add payments, marketing automation or third-party tracking without scope. No fake success messages: persistence must succeed before the form reports success. Label an unconnected form inactive.
4. Confirm deployment scope and intended audience. Default to a private preview. Publish publicly only with explicit authority for that site and audience; draft approval is not publication approval. Follow hosting skill gates. Verify deployment status and returned URL/access state. Never say a private preview is ready for public distribution.
5. Exercise the form with labeled synthetic data when authorized; verify storage readback and exclude tests from results. Respect the Sites skill's verification rules and disclose unavailable checks. Confirm mobile/desktop readiness using supported checks, not unsupported claims of visual review.
6. Agree a validation window and success signal, such as qualified interest or explicit next-step conversations. Distinguish visits, submissions, qualified leads, buying intent and sales; unknown counts stay unknown. No fabricated conversion rate or demand claim.

## Ready for Threads, not automatically posted

Prepare a short benefit-led Threads announcement and reply CTA using the creator's voice. Include the verified public URL only after access is public, plus supported attribution parameters where appropriate. Avoid invented scarcity or commercial proof. Show the exact copy, destination and intended account for review. Publishing/scheduling requires separate explicit authority and verified account identity; verify provider readback before calling it published. If the site is private or the form is unverified, report the remaining distribution blocker instead.

Keep a separate handoff receipt with requested scope, site/version and deployment identifiers when available, URL, visibility, form/storage checks, synthetic-test exclusion, draft/publication state, limitations and next step. Do not rewrite the original decision receipt's `external_actions: 0` to imply that the decision generator deployed anything.
