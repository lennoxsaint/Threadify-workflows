# Research Army: the post step

Threadify writes one compact research post from the winner's backed findings on a proven hook template, the agent adds one Auto Plug for the owner's offer, the owner edits them if they want, and the post is scheduled with its Auto Plug only after one exact "yes". Resolve `scripts/` against the skill directory (one level up from this file). A connection never authorizes scheduling; only the owner's exact "yes" to the post card does.

## Rules

- Threadify writes the post body with `generate_content`. Show its exact text in full, in chat. Never reword it and never use `edit_draft`. Never call `publish_now`.
- The only change the agent may make to the body on its own is casing (lowercase, proper nouns kept), and only when the owner asks; prove it with `scripts/casing-guard.mjs` (`lower(original) == lower(final)` PASS). Wording changes are the owner's: typed into the editable block, or asked for in chat, in which case the agent makes exactly those changes (mode `owner edit`) and re-runs `check-post`.
- **Every post passes `check-post`** before it is shown for approval: no number outside the checker's facts (N posts, K searches and the 30-day window are allowed) and an honest source line ("the N most-liked posts from K keyword searches"), never "top posts", "top on Threads", "most viewed" or "the most-liked Threads posts" without the searches. Never quote other creators' posts or handles.
- **The offer goes in one Auto Plug, never in the body** (the Monetize My Week way). Passing `offer_id` to `generate_content` does not put a link in the post, so do not pass it. When an offer is chosen, the agent writes ONE context-specific Auto Plug from this post's actual findings and the saved offer's approved facts, containing the offer's plain link: `node scripts/research-army.mjs clean-link --link "<saved link>"` removes tracking tags (utm_ and similar), because Threadify already tracks every link it posts. No unsupported urgency, results, user counts or plan claims. Link tracking shows attribution, not causation.
- Without a Threadify connection or generation access, never write the post yourself; say what is missing.
- Open pages for the owner with the host's browser tool when it has one; otherwise run `open -a "Google Chrome" <url-or-file>` (macOS; `open <url>` if Chrome is missing). Confirm it opened before saying it's ready.

## Steps

1. **Offer.** Call `list_offers`. If an offer whose name contains "Research Army" exists, use it without asking and say "Auto Plug: <offer name>." Otherwise, if one offer fits, use it; if several could fit, ask the owner to pick one; with none, say "No offer saved; the post goes out without an Auto Plug." Keep the offer's approved facts and its plain link from `clean-link`. Threadify tracks links on Threads itself, so the plug carries no UTM tags. If `link_tracking` from `get_connection_defaults` is off or unknown, say clicks may not be measured.
2. **Pick a template.** Follow [viral templates](viral-templates.md): the owner's own winning hook shape from `greatest_hits` / the Vault when one fits, otherwise one of the ten. Say "Template: <name>, because <the fact it carries>."
3. **Write and check.** One `generate_content` call: `content_type: "short-form"`, `strict_facts: true`, `selectedModel` from [generation models](generation-models.json) (record the requested and reported model), no `offer_id`, and `inputText` = the `input_text` from `facts` (it ends with the wording rule) plus: "Write one compact research post in my voice for creators in <niche>, using this structure: <the chosen template>. Put the most surprising finding in the first 3 to 5 words, then 2 to 4 findings with their exact numbers, one per line. End with one encouraging so-what line for the reader: what this means they can do, said warmly, not a statistic or a question. About 300 characters or fewer. Use only these numbers and follow the wording rule. No links." Keep Threadify's exact text and `draft_id` (call `save_draft` with the exact text if no draft id comes back). Write the exact text to `<run>/post.txt` and run `node scripts/research-army.mjs check-post --dir <run> --file <run>/post.txt`. A `warnings` entry (over 300 characters) is not a failure; mention it in one line. On FAIL, ask Threadify once for a replacement with the same input and check again; if it fails again, show both problems and stop: say why, and schedule nothing. Save `<run>/post.md` with the template, text, model, draft id and the check result.
4. **Write the Auto Plug** (only with an offer). One short reply, 100 to 250 characters, that continues this exact post from one of its findings to what the offer gives, using only the offer's approved facts, and ends with the offer's plain link (from `clean-link`). Write it to `<run>/plug.txt` and run `check-post --dir <run> --file <run>/post.txt --plug <run>/plug.txt --link "<saved offer link>"`; it must PASS (it fails a plug that still carries tracking tags).
5. **Show both in full** in chat (the post, then "Auto Plug (50 min after): <plug>"), and say which template and findings the post used.
6. **Editable block.** Open the editable blocks with a real **Done editing** button: write `<run>/post-drafts.json` as `{"auto_plugs": <true with an offer, else false>, "posts": [{"id": "post-1", "original": "<Threadify's exact text>"}, {"id": "auto-plug", "original": "<the plug>"}]}` (leave out the plug entry without an offer) and run `node scripts/post-editor.mjs --input <run>/post-drafts.json --output <run>/owner-review.json` in the background. Open the URL it prints (browser tool, or `open -a "Google Chrome" <url>`) and say "Edit it if you like, then press Done editing." Wait for the command to report `owner_review_done`, then read `owner-review.json`. If the owner changed the post's wording, the final text is theirs (mode `owner-requested edit`, never casing PASS); write it to `post.txt` and re-run `check-post`, and say if it fails. A changed plug must still PASS the plug check. If the owner unticked **Include Auto Plugs**, schedule without the plug. Done editing never approves scheduling. If the owner says it's fine as is, skip the editor.
7. **Lowercase (only on request).** `node scripts/casing-guard.mjs lowercase` with the proper nouns to keep, then `check`, and show "guard: lower(original) == lower(final) PASS".
8. **One post card.** Call `best_time_to_post` (owner's timezone) and `list_scheduled_posts`; a truncated response is not an empty calendar. Pick tomorrow's best slot (or the next open best slot) at least 60 minutes from now and not within 90 minutes of another scheduled post; with no history, say the time is general, not measured. Call `validate_post` on the exact final text (and on the plug when there is one). Send one message:

```text
Research Army · @handle · <timezone>
<weekday date, local time> · <unchanged | casing guard PASS | owner edit> · check-post PASS
<exact final post text>
Auto Plug (+50 min): <exact plug text, or "none">
Action: schedule this post with its Auto Plug exactly as shown. Nothing publishes now.
Reply "yes" to schedule it, or "no" to schedule nothing.
```

9. **Schedule.** Only on an exact "yes". Any change to text, plug, link, account or time needs a new card and a new "yes". Re-check `list_scheduled_posts`, then call `schedule_post` once with a stable `idempotency_key` (account, slot, text hash, plug hash, link and delay): unchanged text passes `draft_id` and `content_type`; lowercased or owner-edited text passes the exact final `text` without `draft_id`, because Threadify schedules a draft's stored text when given a `draft_id`. With an offer add `auto_plug: { trigger: "time", delay_minutes: 50, content: <approved plug> }`. Omit `platforms` and `auto_repost`. Read it back with `get_schedule_status` (and `list_scheduled_posts`): account, text, local time and the stored Auto Plug content, trigger and delay must match the card; a failed or cancelled record is a mismatch. Report `scheduled_confirmed`, `blocked`, `failed` or `schedule_unverified`. If the outcome is unclear, read back before retrying, and retry only with the same key. On "no", schedule nothing; the post stays a Threadify draft.
10. **Auto Plug tier-blocked.** If `schedule_post` refuses the Auto Plug for the plan, state the returned current tier, required tier and allowed alternative. Do not retry the denied call and do not pretend the plug is set. Offer to schedule the post without the plug (a new card and a new "yes") and to post the plug by hand as a reply after it goes out.
