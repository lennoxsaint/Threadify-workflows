# Threadify Qualified Buyer Research

Use when a user wants to find current buyer-language posts, reject false-positive leads, stage a useful reply, or learn from completed outreach outcomes without automating sends.

## Instructions

1. Read `workflows/qualified-buyer-research/manifest.json` and `workflows/qualified-buyer-research/README.md`.
2. Verify the intended Threadify account and the visible browser account before any composer action.
3. Use only approved clean audience, offer, proof, voice, and suppression context. Do not place private source material into public examples or receipts.
4. Search problem language, not broad identity labels. Prefer posts from the last 72 hours.
5. Inspect the entire post, visible replies, and profile before evaluating the candidate.
6. Run immutable hard gates before scoring. Reject stale, seller-funnel, teaching, duplicate, suppressed, contradictory, unsafe, or pitch-only candidates.
7. Score pain, intent, fit, warmth, permission-readiness, and risk from 1 to 5, then classify the next stage.
8. A like never creates DM permission. A score never overrides a hard gate.
9. Draft one useful next move. If the user requested staging, type the exact text into the correct composer and stop before send.
10. Show the account, source, evaluation, exact text, destination, and action at the approval gate.
11. Log outcomes and evaluate learning only after the 72-hour outcome window or an earlier terminal outcome.
12. Return a receipt. Treat `no_change_insufficient_evidence` as a successful honest result.

Never click Send, schedule, publish, make a paid ask, or silently change accounts without explicit final approval.
